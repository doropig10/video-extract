# A · 怎么读视频

> 只讲"把视频里的信息可靠地取出来"，不讲怎么排版。
> 笔记格式见 `B_怎么记笔记.md`。
> 适用于任何带讲解的视频：课程、访谈、教程、讲座、复盘。

---

## 第 0 步：先判内容靠什么承载

这一步只决定**主线抓音频还是抓画面**，两条线的机制是共用的。

| 类型 | 特征 | 主线 |
|---|---|---|
| 口播为主 | 讲课、访谈、播客、书评、经验分享 | 音频 + 转写，画面只用于校验专名 |
| 画面为主 | 软件操作、实验、解题、书法、手术 | 抽帧，转写只用于对齐时间 |
| 混合 | 有板书/PPT 的讲课、有演示的讲座 | 音频 + 板书抽帧，**两条都要** |

判错的代价：按口播做操作类，会得到一份"看不懂在干什么"的笔记；按画面做讲课，会得到几百张截图仍然不知道她讲了什么。

---

## 第 1 步：探测

```bash
python -m yt_dlp -I <P> -F "<链接>"
```

必须确认四件事：

1. **是否多分 P** —— 合集必须加 `-I n`，否则会把全部 P 的信息拉一遍
2. **音频最高码率** —— 30280 通常最高，转写优先用它
3. **视频可用画质** —— 读文字用 720P 够，1080P 除非要读小字
4. **有无真字幕轨** —— 见下方分支

> 界面上的"字幕"和接口里的字幕是两回事。`--list-subs` 只显示 `danmaku` 就是没有字幕，那是弹幕，不是台词。

---

## 第 1B 步：有字幕的分支

先拿字幕，再考虑转写——成本差一个数量级。

```bash
python -m yt_dlp --list-subs "<链接>"
python -m yt_dlp --write-subs --sub-langs "zh-Hans,zh-CN,ai-zh" \
  --convert-subs srt -o "out/%(id)s.%(ext)s" "<链接>"
```

三种情况要分清：

| 现象 | 实质 | 处理 |
|---|---|---|
| `zh-Hans` / `zh-CN` / `ai-zh` | 真字幕轨 | 直接拉，秒级 |
| 只有 `danmaku` | 弹幕 XML | 没用，走转写 |
| 画面有字但列表为空 | **硬字幕**（烧进画面） | 当画面文字处理，走第 4 步 |

**AI 字幕（`ai-zh`）需要登录态**——未登录时接口的字幕字段直接为空，你分不清是"没有"还是"被隐藏"。它和通用转写同源同病：英文词照样写成中文谐音，区别只是切句更碎、不会凭空编整句。

**字幕质量三看**：英文术语拼对了吗（拼对了就是免费的校正表）／有没有"嗯、这个、就是说"（有=人工听写）／每条多长（8–12 字一条多半是 AI）。

---

## 第 2 步：取流

两条流分开下，不要合并——合并要 ffmpeg 且体积翻倍。

```bash
# 音频（优先最高码率）
python -m yt_dlp -I <P> -f "ba" -o "out/%(id)s.%(ext)s" "<链接>"

# 视频流（读文字用 720P）
python -m yt_dlp -I <P> -f "30064" -o "out/src_%(id)s.%(ext)s" "<链接>"
```

## 第 3 步：转写

把本地 m4a 喂给语音转写，拿到 `[起, 止, 说话人] 文本`。

**必须预设它有三类错**：

| 类型 | 实测例 |
|---|---|
| 外文词被听成中文谐音 | stalk→stock、limb→lame、rage→"睿智" |
| 近音词互相顶替 | famine / feminine 双双变成 family |
| 语义反转 | "发音开头像 thank" 变成 "发音没有 thank" |

**校正原则**：先看语义通不通，再看上下文能不能反推（拆字可逆吗？相邻有完整例句吗？）。改完逐条标置信度——高（有第二个信源）／中（语境推断）／低（纯猜，宁可留着不改）。

> 最危险的不是错，是错得通顺。`adapt`→`adopt` 这种，句子照样成立，你一眼扫过去不会停。

## 第 4 步：抽帧

先解决工具：`pip install imageio-ffmpeg numpy pillow`（ffmpeg 自带二进制，不用编译）。

### 通用做法

```bash
# 0) ffmpeg 也可能不在 PATH，先取 imageio-ffmpeg 自带二进制的路径
FF=$(python -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())")
# 1) 每 4 秒一帧，缩到 480 宽，只当索引
"$FF" -i src.mp4 -vf "fps=1/4,scale=480:-1" -q:v 6 scan_%04d.jpg
```

2) 不要整幅比对，**只比"文字区"**（通常是画面左侧那一块）做帧间差分；
3) 每个 20 秒窗口取**最静止**的一帧（内容写完、版面不动）；
4) 按相似度去重，再回到原片按全分辨率取帧，裁掉人像，3–4 张拼一页加时间戳，逐页读。

### 按内容调粒度

| 内容 | 抽帧粒度 | 备注 |
|---|---|---|
| PPT / 板书 | 4 秒 + ROI 差分 + 稳定帧 | 一页一字幕，通常 40–60 秒才换一次 |
| 软件操作 / 实验 | 1–2 秒，或按鼠标点击/画面大变化切片 | 步骤之间不能漏帧 |
| 纯人像 / 访谈 | 基本不抽 | 只用来截取说话人表情，价值低 |

### 三个不要

- **不要用场景检测**：纯色背景换文字，直方图几乎不变，`select='gt(scene,0.35)'` 在十分钟里只报 0–3 次。
- **不要裁太窄**：先按 1120 宽试，窄了会把长句尾巴切掉，误判成"被讲师遮挡"。
- **不要指望手写字**：她边讲边写的批注只出现几秒，关键时段要加密到 1–2 秒一帧。

### 写字动画会让自动去重失效

实测：教师边讲边手写板书时，文字区每一帧都在变（笔迹在长），任何"帧间相似度"去重都会退化——646 帧能分出 442 个"版面"、其中 375 个只出现一次。

**这种情况别跟算法较劲**。按固定间隔（3–5 秒）取帧，拼页后**人工合并重复**更快：同一块板子往往出现 2–3 次，肉眼看一眼就知道是同一个词。

## 第 5 步：读画面

不只是读文字。按内容类型看不同的东西：

| 画面里有 | 读什么 |
|---|---|
| 板面文字 | 按固定行结构抄：标题行／属性行／说明行／例句行 |
| PPT | 标题 + 要点层级（缩进即层级）+ 图表标题 |
| 代码 | 语言、关键函数、报错信息（错一个字符就废） |
| 界面 | 菜单位置、按钮名、参数值 |
| 图表 | 坐标轴、单位、基数（"增长 300%" 要看从哪年起算） |
| 手写批注 | 优先抄，它常是讲师临场加的、口述里没有 |

**遮挡处理**：被身体挡住的地方标 `[ ]`，猜不出来就留空。永远允许"未读到"这个状态存在——它比编一个更像真的。

---

## 第 6 步：交叉校验

三份材料，互相验证：

```
板书/画面（最硬，她写下的）
   ↑ 冲突时以它为准
字幕（时间轴准，但可能是 AI 转的）
   ↕
语音转写（口语细节多，但同音词错）
```

**冲突时的处理**：不要合并，**并排保留**，注明各自来源，并给出建议信哪个。

理由：两套一合并，会生成"谁都没讲过、谁都查不到"的第三种——这类错误读起来最顺，因此最难被发现。

---

## 第 7 步：交付前自检

- 每条结论都能回答："这是画面原文、某人说的、还是我补的？"
- 我改过的每一处，都标了置信度吗？
- 没读到的部分，是标了"未读到"，还是偷偷删了？
- 我补的常识，跟原文混在一起了吗？

---

## 边界

**做不到**：付费课程、番剧、充电专属（权限）；多人讨论分不清说话人；纯音乐；靠画面细节传递且帧率极高的内容。

**不该做**：抓下来的内容原样分发。自己看、做笔记可以，搬运是另一回事——工具能力不等于授权。

**成本参考**（42 分钟课）：机器约 3 分钟，人工读图与校对约 50 分钟。**贵的从来不是机器，是读图和对错。**
