视频 → 学习笔记：一套可复用的流程

适用于「有讲解、有板书、需要沉淀成可复习材料」的课程类视频。下面每一步都经过一次完整实测，包含失败项。

实测样本：B 站 42 分钟词汇课（BV1hQk5BAEu2 · p6）｜产出：5 个版本笔记 + 44 个词的完整板书｜工具：yt-dlp + imageio-ffmpeg + 语音转写

STEP 0 的唯一判断：内容靠什么承载？

A 线：口播为主

讲课、访谈、播客、书评、经验分享。

主办：音频。画面只是人像或 PPT 装饰，抽帧只用来校验专有名词。

产出形态：结构化笔记、讲义、逐字稿。

B 线：画面为主

软件操作、实验演示、手术、书法、舞蹈、解题过程。

主办：抽帧。转写只用来对齐时间点，甚至可以不转写。

产出形态：步骤图解、操作清单。

判错的代价：按 A 线做 B 线的内容，你会得到一份"听不懂在干什么"的笔记；按 B 线做 A 线，你会得到几百张 PPT 截图，仍然不知道她讲了什么。

二、七步详情

1探测先看清有什么，再决定下什么
目的拿到分 P 数、时长、可用画质、字幕轨、是否需要登录。这一步决定后面所有取舍。
python -m yt_dlp -I 6 -F "https://www.bilibili.com/video/BVxxxx?p=6"
产物格式清单（音轨 30216/30232/30280，视频 30016=360P 到 30080=1080P）
通过能确认：① 是否多 P（是则必须 -I n）② 音频最高码率 ③ 视频最高可用画质 ④ 有无真正的中文字幕轨
实测坑：多数 B 站视频的"字幕轨"只有 danmaku（弹幕 XML）。CC 字幕或 AI 字幕需要登录态（SESSDATA），没 cookie 时 --list-subs 只能看到弹幕。别指望它。
2取流要什么拿什么，别贪
只要音频-f ba　→ 单文件 m4a，不需要 ffmpeg 合并，最省事
python -m yt_dlp -I 6 -f "ba" -o "out/%(id)s.%(ext)s" "URL"
要画面-f 30064（720P）或 30032（480P）　→ 只取视频流，不合并音频，体积减半
python -m yt_dlp -I 6 -f "30064" -o "out/src_%(id)s.%(ext)s" "URL"
通过文件能正常打开、时长与探测一致
为什么不合并音视频：B 站是 DASH，音视频分离。合并需要 ffmpeg 且体积翻倍。做笔记时画面只用来读文字，720P 够了；音频单独下最高码率，转写更准。
3转写拿到带时间轴的文字
输入上一步的 m4a（支持 m4a/mp3/wav/flv/mp4 等，1GB / 5 小时内）
产物[起, 止, 说话人] 文本 逐段输出，42 分钟约 58 段
通过段数与常识吻合（约每 30–45 秒一段）；抽查开头结尾能对上
必须知道：转写是"按声音写字"。中文课堂里念的英文单词，模型会用中文谐音去对齐——实测 60 个词错了 10 个（16%）：stalk→stock、limb→lame、render→Rainer、famine/feminine 双双变成 family、rage 变成"睿智"。这些错误读起来都很顺，所以危险。
3B有字幕的分支先拿字幕，别急着跑 ASR
判真假字幕轨只显示 danmaku = 没字幕，只有弹幕；出现 zh-Hans／zh-CN／ai-zh 才是真字幕。弹幕不是字幕，别混。
直接取成本几乎为零，秒级完成，优先于转写
# 列出语言轨
python -m yt_dlp --list-subs "URL"

# 取中文轨并转 srt（转格式需要 ffmpeg）
python -m yt_dlp --write-subs --sub-langs "zh-Hans,zh-CN,ai-zh" \
  --convert-subs srt -o "out/%(id)s.%(ext)s" "URL"
质量三看① 英文术语拼对了吗（ASR 的死穴）② 有没有"嗯／这个／就是说"（有→人工听写）③ 每条多长（8–12 字为一条，多半是 AI 字幕）
AI 字幕ai-zh 是 B 站自家 ASR 生成的，需要登录态（未登录时接口的 subtitle 字段直接为空，你分不清是"没有"还是"被隐藏"）。它和通用转写同源同病：英文词照样写成中文谐音，只是切句更碎、不会凭空造整句。UP 主若校对过，质量接近人工。
谁做主字幕管时间轴，ASR 管口语细节，板书管最终裁决。三者冲突时以板书为准。
硬字幕画面里有字、--list-subs 却是空 → 字幕是烧进画面的。这时它属于"画面文字"，直接走 STEP 4 抽帧，别再指望转写。
维度字幕语音转写
时间对齐精确到句粗到段（20–40 秒）
同音词AI 字幕同样会错实测约 16% 出错
说话人不区分可区分
口语语气常被清洗掉保留
凭空生成不会可能整句幻觉
结论：有字幕不等于省掉校对。AI 字幕的错误类型和转写一样（把英文词写成中文谐音），只是它不会编造整句。最省力的组合是——字幕当骨架，转写当补丁，板书当裁判。
4抽帧把 40 分钟压到 20 张图
装 ffmpegpip install imageio-ffmpeg　自带二进制，不用编译、不用改 PATH
低清抽帧每 4 秒一帧、缩到 480 宽，只当索引（42 分钟 ≈ 635 张，25MB）
ffmpeg -i src.mp4 -vf "fps=1/4,scale=480:-1" -q:v 6 scan_%04d.jpg
去重只比"文字区"（左侧 ROI），每个 20 秒窗口取最静止的一帧（写完了、版面不动），再按相似度合并
成像按时间点回到原片按全分辨率取帧，裁掉右侧人像，3–4 张拼一页加时间戳标签，逐页阅读
通过候选帧数 ≈ 词条数 ×1.3；每页文字无需放大即可辨认
别用场景切换检测。绿幕/纯色背景上换文字，直方图几乎不变，select='gt(scene,0.35)' 在 10 分钟里只报 0–3 次切换。必须自己按 ROI 做差分。
5读板书拿到转写里没有的那三样
看什么板面通常有固定的行结构：词 + 音标 / 词性义项 / 记法句 / 例·真题 / 派生。按行抄，不要改写。
为什么值音标、第二三义项、真题原句、派生词——这四样口述里基本没有。实测：stalk 的"跟踪盯梢"、limb 的"大树枝"、bleak 的四个义项，全在屏幕上。
通过每个词条的四要素齐全；被遮挡处用 [ ] 标出，不脑补
讲师会挡住字。长例句的尾部经常被身体压住。多抽几帧、挑她站偏的时刻能缓解，但无法根除——所以永远要允许"未读到"这个状态存在。
6双轨校对板面一套，口述一套，永不合并
核心原则屏幕上的记法和嘴上的记法经常不是同一套。实测 5 处冲突：bark（Buck vs 酒吧后面）、damp（趴 vs place）、limb（立 vs 站在）、bleak（四义 vs 只记荒凉）、humble（hum+able vs 未拆）。
做法每条词固定四行：板面 / 口述 / 例·真题 / 派生。缺哪行就写"（未写记法行）"或"（口述未展开）"，不填空。
为什么两套一合并，就生成了第三种——谁都没讲过的那一种。这是最容易发生、也最难被发现的错误。
通过每条都能回答：这句话是板面原文、她口述、还是我补的？三者之一。
7产出给每条结论打上置信度
结构按讲授顺序或词群分组；每条 = 音标 + 义项 + 记法（分轨）+ 例句 + 派生
标注凡我改的、我补的、我猜的，单独成节或加行内标记；校正表要给置信度
通过读者能只凭文档判断"哪一句可以去考试，哪一句要回原视频核实"

三、质量闸门：四问四答

问自己如果答案是"否"
① 这个错词能被反推吗？
拆字逻辑可逆？相邻有完整英文例句？		 标 中，写进校正表让读者自己回听。别假装确定。
② 这条结论有第二个信源吗？
板面 + 口述 + 例句，三处至少两处一致？		 标 低 或直接删。单信源的结论不要写进正文。
③ 这段画面是我编的吗？它能追溯到某一帧或某一句原话？ 删。详细但不真实的笔记，比简略但真实的危害大得多。
④ 读者知道哪句不是她说的吗？ 把"整理注"从正文里物理隔离出来，单独成节。
一句话原则：不确定的东西不要写得更像真的。笔记的可信度由最模糊那一条决定，不由最漂亮那一条决定。

四、命令库（可直接复制）

装环境

pip install yt-dlp imageio-ffmpeg numpy pillow
python -m yt_dlp --version

探测与取流

# 看格式清单（含分P、画质、字幕）
python -m yt_dlp -I 6 -F "URL"

# 只取音频（推荐，无需合并）
python -m yt_dlp -I 6 -f "ba" -o "out/%(id)s.%(ext)s" "URL"

# 取 720P 视频流（读板书用）
python -m yt_dlp -I 6 -f "30064" -o "out/src_%(id)s.%(ext)s" "URL"

# 看有没有真字幕（多数只有弹幕）
python -m yt_dlp --list-subs "URL"

抽帧与去重

# 1) 每 4 秒一帧，480 宽，只做索引
ffmpeg -i src.mp4 -vf "fps=1/4,scale=480:-1" -q:v 6 scan_%04d.jpg

# 2) 按"文字区"差分，每 20 秒窗口取最静止帧（Python）
#    ROI 取左侧：a[8:80, 4:150]（视画面调整）
#    阈值：窗口内 argmin(diff)，再与已选帧 diff < 5.0 则合并

# 3) 回原片取全分辨率、裁掉人像、拼页
ffmpeg -ss 136 -i src.mp4 -frames:v 1 -vf "crop=1120:720:0:0" -q:v 2 w_136.jpg

批量清理与调用

# 文件太多时 rm 会报 "Argument list too long"，改用 find
find . -maxdepth 1 -name "scan_*.jpg" -delete

# Windows 下从文本读清单，务必去掉 CRLF
tr -d '\r' < list.txt | while read t; do echo "$t"; done

六、这套方法的边界

适合

有讲解的课程、讲座、访谈；有板书或 PPT 的内容；需要反复复习、检索、打印的材料；单集 20–90 分钟。

不适合

纯音乐／演奏；靠画面细节传递的（软件操作、手术、书法）；读音本身就是考点的口语课；多人讨论（说话人分离会串）；只想"大概看看"的视频。

版权边界：付费课程、番剧、充电专属拿不到（权限问题，不是技术问题）；抓下来的内容自己看、做笔记可以，原样搬运分发是另一回事。别把工具能力当成授权。

七、成本参考（42 分钟样本）

环节机器耗时人工耗时
探测 + 取音频约 10 秒—
转写（42 分钟）约 1 分钟—
取 720P + 抽帧 + 去重约 2 分钟—
读板书（44 词 / 18 页）—约 20 分钟
同音词校正 + 冲突比对—约 15 分钟
成稿—约 15 分钟
合计约 3 分钟约 50 分钟
结论：机器几乎不花时间，成本全在读图和对错上。所以真正值得优化的不是脚本速度，而是"少读几张图、少猜几个词"——这正是双轨校对和置信度标注存在的理由。
